## Risks & open questions
- **R-1 — existing selftest fixtures (corrected before approval).** 9 fixtures put an Approved or
  In progress spec in `specs/active/` with no "User experience" heading, so under G-3 the new
  check flags each of them. Eight only assert their own message, so they are unaffected. One is
  not: the criterion-map scenario (`specs/active/0040-map.md`, In progress) asserts
  `doctor --strict` → `exits 0` ("a missing map name stays a WARN under --strict"). The new gate
  would make that exit 1.
  Recommendation: give that one fixture the two lines `## User experience` /
  `none — no user interface`. Its assertion stays exactly as it is, and the fixture is then a
  well-formed current spec, so the test still proves only the map rule. Relaxing G-3 instead would
  weaken the rule. Changing the assertion is forbidden (invariant rule 5).
  Any other red test → stop, R-07.
- **R-2 — G-1 permalink.** The Claude artifact tool keeps a label for each publish and a version
  history that editors can read. I found no documented stable link to a single version.
  Recommendation: the adapter says "publish with label `v<n>`, cite it as
  `· version v<n>`, never overwrite an approved version without R-08". If claude.ai later offers
  per-version links, that is its own small change.
- **R-3 — doctor parses free text.** B-4 showed what that costs. Recommendation: one strict form
  (`- Design:` at the start of a line) plus a fail-closed default. Any other spelling counts as
  missing and warns, which is the safe direction.
- **R-4 — local `.claude/` copy.** The commands under `adapters/claude-code/` change, but the
  local `.claude/` (excluded from git) keeps the old copy. Recommendation: after the merge, run
  `./scripts/init claude-code` again. This only affects this machine.
- Environment: `./scripts/doctor` here reports no `check.conf`, so there are no profiles. This
  repo's check is `doctor --strict` + `selftest`, and both ran green before this work (281/281).
  `selftest` takes more than 10 minutes on Windows/Git Bash. Recommendation: run it locally once
  at the end of BUILD, and rely on CI for the PR.
